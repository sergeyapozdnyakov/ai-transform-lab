# Шаблон запроса данных у клиента

Этот шаблон используется перед расчётом окупаемости и подготовкой выходного отчёта. Запрашивать нужно только те данные, которые действительно нужны для анализа выбранных процессов. Если часть данных чувствительная, можно использовать обезличенные выгрузки или агрегированные показатели.

## 1. Как формулировать запрос клиенту

Пример письма:

> Для предварительной оценки окупаемости нам нужны данные по выбранному процессу за 3-6 месяцев. На первом этапе можно предоставить обезличенные или агрегированные выгрузки. Цель запроса — не контроль сотрудников, а оценка объёма ручной работы, ошибок, задержек, стоимости процесса и реалистичности пилота.

## 2. Универсальный минимальный пакет

Подходит для любого процесса.

### Описание процесса

- краткое описание процесса;
- кто запускает процесс;
- кто участвует;
- чем процесс считается завершённым;
- какие системы используются;
- где остаются таблицы, почта и ручные действия.

### Объёмы и статусы

- количество операций за 3-6 месяцев;
- даты и статусы прохождения этапов;
- количество операций по типам;
- список исключений;
- причины задержек, если фиксируются.

### Трудозатраты

- роли участников;
- примерное время на операцию;
- количество сотрудников в процессе;
- стоимость часа или фонд оплаты труда по ролям;
- доля времени на ручную сверку, поиск, ввод данных, подготовку отчётов.

### Ошибки и потери

- ошибки, возвраты, переделки, претензии;
- стоимость одной ошибки или переделки;
- суммы списаний, штрафов, компенсаций или потерь;
- причины ошибок, если они классифицируются.

### Системы и данные

- список систем;
- владельцы данных;
- схема интеграций, если есть;
- регулярные выгрузки;
- справочники;
- ограничения по доступам и конфиденциальности.

## 3. Для ритейла, дистрибуции и электронной торговли

Нужны данные по выбранным товарным группам или каналам.

### Продажи и остатки

- продажи по дням или неделям за 12-24 месяца;
- остатки по складам, магазинам и каналам;
- отсутствия товара в продаже;
- отмены заказов из-за отсутствия товара;
- сроки поставки;
- минимальные партии;
- перемещения между складами или магазинами.

### Финансовые показатели

- закупочная цена;
- продажная цена;
- валовая маржа;
- списания;
- уценки;
- стоимость хранения, если считается;
- стоимость внутренней логистики, если влияет на процесс.

### Коммерческие факторы

- календарь акций;
- сезонные периоды;
- новые товары;
- снятые с продажи товары;
- изменения цен;
- данные по маркетплейсам и внешним каналам, если они входят в процесс.

### Качество данных

- справочник товаров;
- категории;
- признаки неликвидности;
- причины списаний;
- причины возвратов;
- правила пополнения.

## 4. Для профессиональных услуг и документных процессов

Нужны данные по выбранному типу документов или проектов.

### Объём документов

- количество документов в месяц;
- типы документов;
- среднее количество страниц;
- форматы файлов;
- каналы поступления;
- доля повторяемых документов;
- доля нестандартных документов.

### Трудозатраты и качество

- время первичного разбора одного документа;
- роли, которые участвуют в разборе;
- стоимость часа по ролям;
- количество исправлений;
- типовые ошибки;
- время старших специалистов на проверку;
- сроки передачи материалов на следующий этап.

### Структура данных

- обязательные поля для извлечения;
- чек-листы проверки;
- шаблоны рабочих таблиц;
- примеры обезличенных документов;
- правила эскалации спорных мест;
- критерии качества результата.

### Конфиденциальность

- есть ли персональные данные;
- есть ли коммерческая тайна;
- какие документы нельзя передавать внешним сервисам;
- требуется ли обезличивание;
- кто утверждает доступ к документам;
- где должны храниться результаты обработки.

## 5. Минимальный пакет для первой оценки

Если клиент пока не готов выгружать много данных, достаточно:

1. Описание одного процесса на 1-2 страницы.
2. 10-20 примеров операций или документов.
3. Оценка объёма операций в месяц.
4. Оценка времени ручной обработки.
5. Оценка стоимости часа по ролям.
6. Список типовых ошибок или задержек.
7. Пример текущего отчёта или рабочей таблицы.
8. Список систем, где находятся данные.

Такой пакет не даст точный расчёт, но позволит подготовить первичную гипотезу и список данных для следующего шага.

## 6. Что можно обезличить

Обычно можно обезличить:

- названия клиентов;
- персональные данные;
- номера договоров;
- реквизиты;
- коммерческие условия;
- адреса;
- имена сотрудников;
- чувствительные комментарии.

Важно сохранить структуру данных: даты, статусы, типы операций, суммы в диапазонах, длительность этапов, причины ошибок и последовательность действий.

## 7. Что не нужно запрашивать на первом этапе

Чтобы не перегружать клиента, на первой оценке обычно не нужны:

- полный архив переписки;
- все документы компании;
- доступы в рабочие системы;
- персональные данные без необходимости;
- коммерческие условия по всем клиентам;
- техническая архитектура в деталях, если процесс пока не выбран;
- данные за много лет без понятной причины.

## 8. Контрольный список перед расчётом

Перед расчётом окупаемости проверить:

- выбран один конкретный процесс;
- есть объём операций;
- понятна текущая ручная работа;
- есть стоимость часа или затратная база;
- есть ошибки, потери, задержки или иной измеримый эффект;
- понятна стоимость запуска и поддержки;
- есть ограничения по данным;
- согласовано, какие числа являются фактическими, а какие оценочными.

## 9. Как фиксировать качество данных

Для каждого источника данных в отчёте стоит указать качество:

| Источник             | Полнота | Достоверность | Ограничения             | Можно использовать в расчёте |
| -------------------- | ------- | ------------- | ----------------------- | ---------------------------- |
| Выгрузка продаж      | Высокая | Средняя       | Нет данных по акциям    | Да, с оговоркой              |
| Таблица ручных задач | Средняя | Низкая        | Заполняется нерегулярно | Только для оценки диапазона  |
| Примеры документов   | Высокая | Высокая       | Требуется обезличивание | Да                           |

Если качество данных низкое, это не провал аудита. Это отдельный вывод: перед пилотом нужно улучшить данные или сузить сценарий.
