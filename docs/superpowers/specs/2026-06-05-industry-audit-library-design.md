# Design: отраслевые рабочие материалы для аудита возможностей искусственного интеллекта

Дата: 2026-06-05

## Цель

Создать локальную рабочую библиотеку для подготовки и проведения аудита возможностей искусственного интеллекта в среднем бизнесе. Библиотека нужна не как публичный маркетинговый текст, а как основа для интервью с клиентом, сбора фактов, подготовки чек-листов, расчётов окупаемости и будущих примеров отчётов для сайта `pozdnyakov.io`.

Материалы должны помогать быстро показать потенциальному клиенту: какие процессы будут разобраны, какие данные понадобятся, где может появиться экономический эффект, что можно улучшить без искусственного интеллекта, а где искусственный интеллект действительно уместен.

## Выбранные направления

Работа начинается с трёх операционных архетипов:

1. Ритейл, дистрибуция и электронная торговля.
2. Профессиональные услуги: аудит, право, бухгалтерия, консалтинг.
3. Логистика, склад, доставка и сервисные операции.

Это не жёсткие отраслевые рамки, а типы операционной модели. Они покрывают большую часть повторяемых ситуаций в среднем бизнесе: товарные потоки, документы, клиентские запросы, складские операции, финансовый контроль, ручные сверки, управленческую отчётность и работу экспертных команд.

## Источники и рыночная рамка

Материалы опираются на открытые источники и практическую управленческую логику. Используются только нейтральные формулировки, без утверждений о фактических клиентских результатах, если такие факты не предоставлены отдельно.

Основные внешние источники:

- Росстат, "Малое и среднее предпринимательство в России 2024".
- НИУ ВШЭ, материалы об использовании искусственного интеллекта российскими компаниями.
- НИУ ВШЭ, "Искусственный интеллект в России: разработка и применение".
- Отраслевые обзоры по LegalTech, WMS, складской и транспортной автоматизации.

## Структура локальных материалов

Материалы создаются в отдельной рабочей папке внутри проекта:

`docs/client-audit-library/`

Планируемые файлы:

- `00-market-archetypes.md` — почему выбраны три направления и какие типы компаний они покрывают.
- `interview-program.md` — программа интервью по ролям: собственник, генеральный директор, операционный директор, финансовый директор, ИТ-директор, руководители функций.
- `process-card-template.md` — единый шаблон карточки процесса.
- `01-retail-distribution.md` — процессы и сценарии для ритейла, дистрибуции и электронной торговли.
- `02-professional-services.md` — процессы и сценарии для аудиторских, юридических, бухгалтерских и консалтинговых компаний.
- `03-logistics-warehouse.md` — процессы и сценарии для логистики, склада, доставки и сервисных операций.
- `sample-report-backlog.md` — перечень будущих публичных примеров отчётов для сайта.

## Формат карточки процесса

Каждый процесс описывается по единому шаблону:

- Процесс и бизнес-цель.
- Типичные участники.
- Возможные варианты процесса в компании.
- Часто используемые информационные системы.
- Где обычно остаётся ручной труд.
- Типовые узкие места.
- Вопросы для интервью.
- Какие данные запросить.
- Метрики для оценки эффекта.
- Улучшения без искусственного интеллекта.
- Возможные решения с искусственным интеллектом.
- Что проверить перед запуском пилота.
- Как считать предварительную окупаемость.

## Тон и ограничения

Язык профессиональный, с приоритетом русских формулировок без англицизмов там, где есть точный русский аналог. Термины вроде WMS, CRM, ERP допустимы, если это название класса систем, но рядом нужно давать понятное объяснение.

Запрещено:

- Выдавать типовые сценарии за реальные клиентские кейсы.
- Указывать точные проценты экономии без исходных данных.
- Обещать внедрение искусственного интеллекта как обязательный результат.
- Подменять аудит продажной презентацией конкретных инструментов.
- Делать текст слишком общим: каждая карточка должна содержать проверяемые вопросы, данные и метрики.

## Как материалы будут использоваться

Первый уровень использования — внутренняя подготовка к клиентским встречам: брифинг, интервью, запрос данных, первичная оценка эффекта.

Второй уровень — подготовка публичных примеров для сайта: из рабочих материалов выбираются 1-2 сценария на направление и превращаются в аккуратные демонстрационные фрагменты отчёта. Публичные примеры должны явно помечаться как типовые, а не как реальные клиентские результаты.

## Критерии готовности

Материалы считаются готовыми для первого использования, если:

- по каждому из трёх направлений описано не менее 8 процессов;
- для каждого процесса есть вопросы интервью, данные, метрики и варианты улучшений;
- есть единая программа интервью по ролям;
- есть перечень 5-7 кандидатов на публичные примеры отчётов для сайта;
- текст не содержит вымышленных клиентских результатов;
- материалы можно использовать как основу для звонка с потенциальным клиентом без дополнительной расшифровки терминов.
