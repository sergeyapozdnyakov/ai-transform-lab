# Design: примеры расчёта окупаемости и выходных документов

Дата: 2026-06-05

## Цель

Создать локальный пакет материалов, который показывает, что клиент получает после аудита возможностей искусственного интеллекта: расчёт окупаемости, фрагменты выходного отчёта, список данных, карту процесса, дорожную карту пилота и ограничения расчёта.

Пакет нужен для двух задач:

1. Внутренняя работа с потенциальным клиентом: подготовка к звонку, запрос данных, демонстрация логики расчёта.
2. Будущие публичные материалы сайта: аккуратные типовые примеры без утверждений о фактических клиентских результатах.

## Выбранный подход

Используется вариант 3: полный внутренний набор консультанта.

В пакет входят:

- универсальный шаблон расчёта окупаемости;
- пример для ритейла, дистрибуции и электронной торговли: неликвиды и отсутствие товара в наличии;
- пример для профессиональных услуг: первичный разбор документов;
- структура выходного отчёта после аудита;
- шаблон запроса данных у клиента.

## Структура файлов

Материалы создаются в папке:

`docs/client-audit-library/roi-output-examples/`

Планируемые файлы:

- `00-roi-model-template.md` — универсальная модель расчёта окупаемости.
- `01-retail-stock-roi-example.md` — типовой расчёт по запасам, дефициту и неликвидам.
- `02-document-intake-roi-example.md` — типовой расчёт по первичному разбору документов.
- `sample-output-report-structure.md` — структура выходного отчёта для клиента.
- `client-data-request.md` — список данных, которые нужно запросить перед расчётом.

## Единый формат ROI-примера

Каждый пример должен содержать:

- типовую ситуацию;
- для кого пример понятен;
- исходные допущения;
- какие данные нужно заменить на данные клиента;
- формулы расчёта;
- три сценария: консервативный, базовый, высокий;
- период окупаемости;
- что входит в выходной документ;
- какие решения без искусственного интеллекта проверяются первыми;
- где искусственный интеллект может дать дополнительный эффект;
- риски, ограничения и условия пилота.

## Правила допущений

Все числа в примерах являются демонстрационными. Они должны быть явно помечены как типовые допущения для иллюстрации методики.

Запрещено:

- писать, что такой результат уже получен клиентом;
- обещать конкретную экономию;
- использовать формулировки "гарантированный эффект" или похожие;
- скрывать стоимость внедрения;
- считать только экономию времени и игнорировать стоимость владения решением;
- предлагать искусственный интеллект там, где сначала нужны данные, регламенты или обычная автоматизация.

## Требования к языку

Язык профессиональный и русский. Допустимы общеупотребимые сокращения вроде ROI только в названии файла или рядом с русским объяснением "окупаемость инвестиций". В тексте предпочтительны формулировки "окупаемость", "годовой эффект", "стоимость владения", "период окупаемости".

Текст должен быть понятен собственнику, генеральному директору, операционному директору и финансовому директору без технического погружения.

## Проверка готовности

Пакет считается готовым, если:

- создано 5 файлов;
- оба примера содержат формулы, сценарии и период окупаемости;
- в каждом примере есть блок ограничений;
- есть шаблон запроса данных;
- есть структура выходного отчёта;
- материалы не содержат утверждений о фактических клиентских результатах;
- материалы можно использовать как основу для будущего публичного примера на сайте.
