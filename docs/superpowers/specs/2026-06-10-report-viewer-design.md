# Интерактивный просмотрщик отчёта в блоке «На выходе»

## Цель

Поднять конверсию в заявку через контактную форму, устранив главный разрыв воронки:
блок «На выходе» обещает отчёт 30–50 страниц, а ссылка «открыть пример отчёта» ведёт
на тонкую статичную страницу из пяти коротких секций. Клиент не видит подтверждения
ценности. Решение — листаемый «просмотрщик отчёта» прямо на лендинге, собранный из
готового контента библиотеки `docs/client-audit-library/`.

Решение принято в пользу удержания на лендинге (а не отдельной страницы): форма
заявки живёт здесь же, интерактив работает на доверие в точке конверсии.

## Размещение и связь с существующим блоком

Просмотрщик добавляется внутрь секции `AuditOutput` в
`src/components/landing/Sections.tsx`, под четырьмя карточками результата, перед
панелью пост-сопровождения.

Карточки становятся точками входа в просмотрщик (вместо нынешних разрозненных
ссылок):

| Карточка            | Сейчас ведёт                     | Будет вести                      |
| ------------------- | -------------------------------- | -------------------------------- |
| Отчёт 30–50 страниц | `/docs/sample-audit-report.html` | раздел 01 просмотрщика           |
| Расчёт окупаемости  | `#roi` (калькулятор)             | раздел 05 просмотрщика           |
| Дорожная карта      | `#deliverable` (виджет)          | раздел 06 просмотрщика           |
| Пакет для старта    | `#contact` (форма)               | финальный CTA-экран просмотрщика |

Клик по карточке прокручивает к просмотрщику и открывает нужный раздел.
ROI-калькулятор и карта процессов остаются на своих местах ниже по странице.
Ссылки на статичные HTML-документы в футере не меняются.

## Контент просмотрщика

Семь разделов. Источник — `docs/client-audit-library/roi-output-examples/sample-output-report-structure.md`
и обезличенный retail-пример `01-retail-stock-roi-example.md`:

1. Управленческое резюме — главные выводы и эффекты.
2. Границы аудита — что вошло, что нет, на чём основаны расчёты.
3. Карта процессов — таблица «этап / участник / ручная работа / возможность».
4. Реестр узких мест — гипотезы с метрикой проверки и приоритетом.
5. Расчёт окупаемости — три сценария (консервативный, базовый, высокий), окупаемость.
6. Дорожная карта 90 дней — таблица по неделям.
7. «Полный пакет — по запросу» — CTA-экран (см. ниже).

Требования к контенту:

- обе языковые версии, RU и EN, одинаковые по смыслу;
- везде пометка «пример структуры, обезличено» — без выдуманных названий клиентов;
- номера страниц («стр. 4 / 38») декоративные, но согласованы с обещанием
  «30–50 страниц» в карточке блока;
- русская версия без лишних англицизмов, как в остальном сайте.

## Архитектура

- Новый компонент `src/components/landing/Widget5ReportViewer.tsx` — в стиле
  существующих виджетов (mono-лейблы, цветовые переменные темы, бордеры).
- Контент разделов — в отдельном модуле `src/components/landing/report-content.ts`
  со структурой `{ ru: Section[], en: Section[] }`. В `i18n.tsx` (уже ~100 КБ)
  контент не добавляется; язык берётся из `useI18n()`.
- Состояние — `useState` с индексом активного раздела. Переходы между разделами —
  `framer-motion` (уже в зависимостях).
- Десктоп: оглавление слева (как в мокапе), контент справа, нижняя панель с
  навигацией «назад/вперёд» и CTA. Мобайл: оглавление сворачивается в
  горизонтальную ленту чипов над контентом.
- Элементы: счётчик страниц в шапке, тонкий прогресс-бар, кнопки навигации.

## Механика CTA

- Финальный раздел 07 — экран со списком полного пакета: ROI-модель с формулами,
  черновик требований к пилоту, критерии выбора подрядчика, программа интервью.
- Кнопка «Получить полный пример пакета» открывает существующий `ContactModal`
  (через проп `openModal`, как у остальных секций). Новых полей и бэкенда нет.
- Доставка пакета — вручную по заявке: форма уже шлёт в CRM (`/api/contact`)
  с mailto-фолбэком.
- CTA дублируется в нижней панели просмотрщика на всех разделах.

## Анимация

Умеренная и только внутри блока: fade + лёгкий сдвиг при смене раздела,
анимация ширины прогресс-бара. Новых эффектов в других секциях лендинга нет.

## Обработка ошибок и крайние случаи

- Контент статический, сетевых запросов нет — состояний загрузки/ошибки не требуется.
- Длинные таблицы на мобайле: горизонтальный скролл внутри контейнера раздела,
  без ломки сетки (на лендинге уже есть паттерн `min-w-0` + `overflow`).
- Смена языка RU/EN на открытом просмотрщике сохраняет активный раздел.

## Проверка

Локально перед сдачей:

- `bun scripts/validate-site-content.mjs` (контентный валидатор);
- eslint по затронутым файлам;
- прод-сборка `bun --bun run build`;
- отсутствие автогенерированного хвоста в `src/routeTree.gen.ts` после сборки;
- ручная проверка: открытие каждого раздела с карточек, переключение RU/EN,
  мобильная ширина 390px, открытие `ContactModal` с финального экрана.

Деплой на продакшен — только после отдельного подтверждения Сергея.

## Вне рамок

- Отдельная страница `/sample-report` (возможный следующий шаг — контент уже
  будет вынесен в `report-content.ts`, переиспользовать просто).
- Реальный PDF полного пакета — отправляется вручную по заявке.
- Правки других секций лендинга и новые анимации вне блока «На выходе».
- Изменения статичных документов в `public/docs/`.
